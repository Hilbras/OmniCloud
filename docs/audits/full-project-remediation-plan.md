234 raw findings across 12 areas; after merging duplicates (many areas re-reported the same WebDAV, OCE2, FK, and search defects) roughly 150 distinct issues remain.

Verified critical defects (fix first; each has a data-loss, crash, or release-blocking consequence):

1. **Permanent delete violates the `currentVersionId` FK.** `deleteVersionsByFileIds` runs before the `File` delete, while the FK is `ON DELETE NO ACTION`. Telegram objects are already removed, so metadata is orphaned and every versioned delete/purge fails. — `packages/core/src/services/file-service.ts:767`, `packages/database/src/index.ts:1041`, `packages/database/prisma/migrations/10_file_current_version_fk/migration.sql`
2. **WebDAV auth and stream errors crash the process.** Auth resolution runs before the `try`; a malformed cookie or DB error rejects unhandled. `stream.pipe(response)` has no error handler. No `unhandledRejection` guard. — `apps/api/src/webdav/server.ts:41,54,119`
3. **WebDAV write flag is never enforced**, and the live listener lists/serves trashed files, cannot address nested/root files, and does not decode/encode paths. — `apps/api/src/webdav/server.ts:61,103,138-183`
4. **`apps/api` does not typecheck**, so CI is red. — `apps/api/src/webdav/{routes,server}.ts`, `apps/api/test/{harness,webdav-routes.test}.ts`
5. **OCE2 "hidden name" files download as ciphertext** and reveal the real name on rename; hide-name never creates the index entry, so the real name is lost. — `apps/web/src/api/download.ts:271`, `apps/web/src/lib/rename-metadata.ts:14`, `apps/web/src/hooks/useItemActions.tsx:296`
6. **Desktop app cannot boot.** It spawns the server with empty Telegram/encryption env, never loads a `.env`, never runs migrations, and the preload path points at a non-existent file. Release artifacts upload from the wrong directory. — `apps/desktop/main.ts:51,158,175`, `.github/workflows/desktop.yml`
7. **Multipart fields placed after `file` are ignored**, so the documented curl order silently drops `folderId` and all encryption fields (uploads stored as plaintext). — `apps/api/src/routes/files.ts:82,180`
8. **Telegram upload cancellation never fires** (`Object.assign` snapshots the getter as `false`), and `USER_CANCELED` is mapped to a retryable connection error. — `packages/telegram/src/provider.ts:94`
9. **A truncated reconciliation scan trashes valid old files in bulk.** `truncated` is reported but repair planning still emits `detach-*` for every reference outside the 5000-message window. — `packages/core/src/services/reconciliation-service.ts:23`, `reconciliation-repair.ts:43`

Also confirmed: QR status GET can issue a session cookie (login-CSRF shape); WebDAV session cache bypasses revocation; cached storage engines keep dead Telegram clients after logout/reconnect; recent/local-search DTOs omit encryption fields; upload idempotency fingerprint omits encryption metadata; crash-left `UPLOADING`/`COMMITTING` operations with `telegramMessageId === null` have no recovery; folder delete/purge can delete a parent whose child is still `Restrict`-protected.

## Definition of done

A phase is done only when:

- every listed defect is fixed against current source, not assumed fixed from an older report;
- each critical/high fix has a regression test that fails on the previous code (database-backed where the defect is FK/query-specific);
- `pnpm typecheck`, `pnpm lint`, `pnpm format:check`, `pnpm test` pass from a clean checkout with no local build artifacts;
- behaviour-affecting changes update `docs/api.md` / `docs/deployment.md` / `docs/sdk.md` / `README.md` in the same change;
- the real user scenario is exercised end-to-end, not only unit tests: sign in, upload (plaintext/OCE1/OCE2), rename, download, search, trash→restore→purge, reconnect, WebDAV mount, desktop launch.
